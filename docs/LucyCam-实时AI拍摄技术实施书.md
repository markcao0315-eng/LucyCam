## 三 技术决策

采用「云端一次构图规划，加手机本地连续追踪」。保留 Render 和 Gemini；不增加 GPU 服务器、视频流上传或新数据库。

| 环节 | 执行位置 | 具体职责 |
| --- | --- | --- |
| 相机与画面采样 | iPhone 浏览器 | 持续预览、缩小帧、记录当前画面几何 |
| 构图规划 | Render → Gemini | 返回主体框、目标裁切、滤镜建议和短说明 |
| 图像追踪 | 浏览器 Worker | 跟踪画面特征，估算参考画面到当前画面的变换 |
| 目标圈与对准 | 浏览器主线程 | 映射目标、显示箭头、检查对准和稳定 |
| 数字缩放及滤镜 | 浏览器 | 统一变换预览和照片导出 |
| 拍摄与清晰度筛选 | 浏览器 | 取少量候选帧，选一张并导出 |
| 保存 | 用户及系统分享界面 | 点击保存或长按照片，不自动调用系统分享 |

每轮正常流程只调用一次 Gemini。追踪和稳定判断不产生额外 AI 调用。第一版追踪丢失后暂停，让用户点「重新分析」，不要在后台无限重试或持续上传。后续可扩展最多一次复核，但仍必须计入现有额度。

首版统一使用数字缩放，降低 Safari 硬件差异和追踪坐标跳变风险。硬件变焦作为后续增强：必须检测实际能力、应用后读取设置，并重新建立追踪参考。浏览器规范中存在 zoom，并不表示用户的 iPhone 当前视频轨道一定支持。[相机能力依据](https://www.w3.org/TR/image-capture/)

## 五 坐标规范

### 坐标空间

所有几何计算统一使用**未镜像、未滤镜、未数字缩放**的相机画面。仅在最终显示和导出时按自拍设置镜像一次。原有 `/api/compose` 的镜像行为保持不变；新接口使用以下规则，不可混用。

定义四个空间：

- `F0`：发出 AI 请求时的完整视频像素平面，尺寸来自 `video.videoWidth / video.videoHeight`。
- `A0`：F0 中按选定比例做 `object-fit: cover` 对应中心裁切后的画面，也是上传给 AI 的内容；缩小至最长边 1024 后上传，宽高比不变。
- `Ft`：当前完整视频像素平面，可能已经因用户转动手机而与 F0 不同。
- `Vt`：用户看到的取景器 CSS 像素平面，包含当前数字裁切和可选镜像，不包含外部按钮。

跟踪器对完整未镜像视频采样，缩小并保留原始宽高比，最长边初始设为 480。不能把已经滤镜、镜像、数字变焦后的显示画布输入跟踪器。

### 从 AI 目标到实时画面

设 A0 在 F0 中的裁切为 `B0 = {sx, sy, sw, sh}`。AI 返回的 `(cx, cy)` 是 A0 中归一化的裁切中心。

```text
p0 = [B0.sx + cx * B0.sw, B0.sy + cy * B0.sh, 1]

pt = T0t * p0
```

`T0t` 把 F0 的像素坐标映射到 Ft。初版采用二维相似变换，包含平移、旋转和统一缩放。若在低分辨率跟踪坐标中得到变换 `H0t`，以 `D0`、`Dt` 表示原始视频到跟踪尺寸的缩放矩阵，则：

```text
T0t = inverse(Dt) * H0t * D0
```

设当前真正显示的裁切为 `Ct = {sx, sy, sw, sh}`，取景器显示宽高为 `(VW, VH)`：

```text
u = (pt.x - Ct.sx) / Ct.sw
v = (pt.y - Ct.sy) / Ct.sh

displayX = (mirrored ? 1 - u : u) * VW
displayY = v * VH
```

对准距离用当前画面尺寸归一化，不使用设备像素比，也不能直接比较 CSS 像素和视频像素。目标在取景范围外时显示边缘箭头；逻辑仍使用原始越界坐标，不能把它夹到边缘后当成“已对准”。不要让准星追着目标动：准星固定在视图中心，目标圈随真实画面变换移动。

### 对准后的裁切

AI 裁切的四个角先由 A0 映射到 F0，再通过 T0t 映射到当前 Ft。禁止继续使用 F0 的原始像素裁切坐标拍摄新画面。

在对准锁定帧 L 上，以变换后的目标中心 `pL` 为中心，找出能包含四个目标角、且保持选定宽高比的最小轴对齐矩形。计算方法：设半宽、半高需求分别为 `dx`、`dy`，当前 1× 基础视口大小为 `(Bw, Bh)`，则 `k = max(2*dx/Bw, 2*dy/Bh)`，目标裁切大小为 `(k*Bw, k*Bh)`，相对数字倍率为 `1/k`。

再按视频边界和输出像素下限限制倍率。矩形越界、变换失真或不能包含主体时，回到引导或提示重试，不能偷偷移动裁切中心后宣称对准。允许微小浮点误差的边界修正，并为此写测试。

锁定后预览平滑过渡到该裁切；稳定阶段使用这份锁定的 `CaptureConfig`。若用户又明显移动，退出缩放、回到引导并重新锁定，不能用不断追随主体的数字裁切伪装“手机已经稳定”。

旋转屏幕、改变照片比例、切换镜头或 `videoWidth/videoHeight` 变化，都使本轮参考失效。取消旧请求和追踪，回到准备状态。

## 六 Gemini 接口和校验

保留 `/api/compose` 的现有请求和响应，新增 `POST /api/guide-plan`。两条收费路径必须共用同一实例的会话、并发、冷却、小时和日限额，不能为新接口再创建一套可绕过额度的 `createAI()`。

请求示例：

```json
{
  "referenceId": "browser-generated-uuid",
  "scene": "travel",
  "aspectRatio": "3:4",
  "image": "BASE64_JPEG_WITHOUT_DATA_URL_PREFIX"
}
```

成功响应示例，数值仅为接口样例，不是真实 AI 结果：

```json
{
  "schemaVersion": 1,
  "referenceId": "browser-generated-uuid",
  "model": "gemini-3.1-flash-lite",
  "plan": {
    "canGuide": true,
    "subject": {
      "label": "自行车",
      "box": {"x": 0.35, "y": 0.58, "width": 0.3, "height": 0.2}
    },
    "crop": {"centerX": 0.55, "centerY": 0.6, "scale": 0.7},
    "filter": {"id": "clear", "strength": 35},
    "advice": "保留海面，减少两侧杂物。"
  }
}
```

模型只生成 `plan`；服务端补充版本、实际模型 ID 和原样回显的 `referenceId`。参考 ID 仅用于关联本轮请求，不是权限凭据。

| 字段 | 约束 |
| --- | --- |
| `referenceId` | 1–64 位字母、数字、连字符；格式不正确返回 400 |
| `scene` | 仅 `portrait`、`travel`、`landscape` |
| `aspectRatio` | 仅 `3:4`、`1:1`、`9:16`；和 JPEG 实际尺寸比例一致，允许整数缩放舍入误差 |
| JPEG | 保留现有请求体大小、格式和最长边 1280 校验；前端默认上传最长边 1024 |
| `canGuide` | 布尔值；false 时给建议但不进入自动拍摄 |
| `subject.box` | 四项为有限数值，宽高大于 0，矩形位于 `[0,1]` 内 |
| `crop.scale` | 新接口范围 `[0.5,1]`，宽高同时乘此系数；旧接口仍保留 `[0.65,1]` |
| `crop.centerX/Y` | 各自在 `[scale/2, 1-scale/2]` 内，裁切完全在参考图内 |
| `filter.id` | 仅当前的 `original / clear / warm / film / mono` |
| `filter.strength` | 整数 0–100；服务端和前端都校验 |
| 文案 | 主体不超过 100 字符，建议不超过 300 字符；仅用 textContent 显示 |

原图已合适时返回中心 `(0.5,0.5)`、scale=1，不强制移动或放大。难以确定主体、画面模糊或无法合理规划时返回 `canGuide=false`，不得编造定位。主体框应覆盖完整主体；服务端检查最终裁切能保留主体框，边界容差和拒绝逻辑集中配置。首版宁可保留原图或要求重试，也不自动裁断主要人物。

提示词说明坐标空间、禁止执行图片中的文字指令、不识别人名、不推断敏感属性。不要让模型输出任意 CSS、JavaScript、URL 或可执行滤镜字符串。继续使用结构化输出、服务端二次校验及固定模型配置，浏览器不能任意指定 provider、模型或系统提示词。

对无效几何返回可理解的错误，不把无效坐标夹到合法范围后伪装为模型建议。只容许非常小的数值舍入修正。主体和滤镜建议均不代表审美上的唯一最佳结果，预览中应能还原。

保持现有 25 秒模型超时、无自动付费重试和安全错误处理。可在受保护响应中补充非敏感错误分类帮助排障，但禁止返回原始 provider 错误正文、密钥、请求图片或认证头。

## 七 本地追踪实现

优先验证官方 OpenCV.js 固定版本的 `goodFeaturesToTrack` 和 `calcOpticalFlowPyrLK`，它们分别用于找角点及追踪相邻帧特征。[官方光流说明](https://docs.opencv.org/4.x/db/d7f/tutorial_js_lucas_kanade.html)

第一步先完成最小可运行实验：浏览器加载运行时、创建 Worker、输入两张图，返回实际点位移动。检测需要的函数是否存在、初始化是否异步、Worker 中是否可运行；不要根据 C++ 文档假定 JS 构建一定导出了某个函数。OpenCV 有官方预构建及构建流程，采用固定来源、版本和校验值，记录许可证。[官方构建说明](https://docs.opencv.org/4.x/d4/da1/tutorial_js_setup.html)

依赖运行文件自托管到 `dist/vendor/`，不用生产环境的可变 CDN latest 地址。若发布物包含 `.wasm`，在 `server.mjs` 白名单中加入精确文件名和 `application/wasm` 类型；验证 Worker 内资源定位。首版不要求多线程 WASM 或 SharedArrayBuffer，不为此增加跨源隔离配置。

### 每帧处理

1. 主线程从原始 video 生成保留比例的小图，附上 `runId`、`frameId`、媒体时间和尺寸。优先在新视频帧回调中采样；无该能力则使用节流的动画回调并跳过重复帧。
2. Worker 同时最多处理一帧，忙时丢弃待处理旧帧；不能积累队列造成目标圈延迟。初始目标 10–15 次追踪更新/秒，UI 可独立刷新。
3. 灰度转换，按网格分布选取约 80–120 个角点，避免点都聚集在一个移动的人身上。
4. 用金字塔 LK 追踪，初始窗口 21×21、金字塔 3 层；进行前后向一致性检查，丢弃高误差和越界点。
5. 从可靠点估算二维相似变换。若 JS 构建没有所需的鲁棒估算函数，可实现有测试覆盖的两点 RANSAC，再对内点做最小二乘精化，不得因此退化为固定圆点动画。
6. 将相邻帧变换按正确顺序累乘到本轮参考。定期补点，但新增点的坐标锚定到当前参考链，不能补点时把 AI 的参考关系丢掉。
7. 返回变换、内点数、内点比例、残差、空间覆盖、运动速度和帧时间；不把所有图像帧留在内存中。

相似变换形式为 `x'=a*x-b*y+tx; y'=b*x+a*y+ty`。所有矩阵方向、乘法顺序和低分辨率换算均有单元测试。它是首版小角度近似，不是三维姿态恢复；明显视差、旋转和透视变化应降低质量或判为丢失。

### 稳健性和失效处理

以下是待真机调整的初始阈值，不是已达到的实测指标：有效内点不少于 20、内点比例不少于 0.65、前后向误差中位数不超过约 1.5 个跟踪像素、运动模型残差不超过约 2 个跟踪像素。另要求特征覆盖多个区域，不能只看数量。

收到 AI 主体框后，将主体内外的点分组。优先用主体外的静态背景估算相机运动，比较主体点是否相对背景单独移动；主体跟踪证据不足或移动明显时，禁止自动快门。纯天空、白墙或主体占满画面而缺少稳定特征时，应提示“暂时无法稳定跟踪，可手动拍摄”。

开始上传参考帧时就启动本地追踪，AI 返回后用已维护的参考变换映射目标。若请求期间已跟丢、后台暂停或等待超过本轮有效期，丢弃该结果并要求重新分析，不能将旧目标贴在新画面上。建议本轮参考最长保留 20 秒，超过后停止自动拍摄；可在可靠关键帧重定位实现后再放宽。

连续质量差超过约 300 毫秒进入 LOST；期间禁止累积对准时长。Worker 单次结果过旧也不能触发快门。屏幕可平滑显示圆环，但对准判定使用可信的最新原始估计，不能靠动画插值宣布成功。

Worker 退出时释放所有 OpenCV Mat、TypedArray 引用和 ImageBitmap；新一轮不能残留上一轮消息。10 分钟运行测试检查内存是否持续增长。Worker 或 WASM 加载失败时普通相机仍能工作。

## 八 状态机和自动拍摄

```text
IDLE → ANALYZING → GUIDING → ALIGNING → ZOOMING → SETTLING → CAPTURING → REVIEW
                    ↓          ↓          ↓           ↓
                   LOST ← 追踪质量不足、目标移动、帧过旧

用户取消 / 镜头或比例改变 / 屏幕方向改变 / 页面隐藏 → 取消本轮 → IDLE
网络或模型错误 → 可重试错误状态，保留普通相机
```

| 状态 | UI 和行为 | 退出条件 |
| --- | --- | --- |
| IDLE | 普通相机；「AI 帮我拍」按钮；自动拍摄开关清楚可见 | 用户启动本轮 |
| ANALYZING | 当前取景继续，提示“分析中，请保持片刻”；可以取消 | 有效 AI 结果和可靠参考追踪 |
| GUIDING | 固定中心准星、随画面移动的目标圈、方向箭头 | 目标进入对准范围 |
| ALIGNING | 目标圈变色，显示稳定进度 | 连续满足对准和稳定条件 |
| ZOOMING | 约 400–700 毫秒平滑过渡至最终裁切和滤镜 | 动画完成，追踪仍可靠 |
| SETTLING | 提示“保持不动，即将拍摄”；允许取消 | 再稳定约 600 毫秒 |
| CAPTURING | 原子锁定本轮拍摄，采集候选图 | 导出成功或明确报错 |
| REVIEW | 显示成片、还原原片和保存按钮；不再自动拍第二张 | 用户返回或启动新一轮 |
| LOST | 停止进度与自动快门，显示重试或手动拍摄 | 用户重新分析或退出 |

初始对准条件：目标到中心距离小于取景器短边的 3%，连续 800 毫秒，同时跟踪有效且运动速度低于短边约 1%/秒。退出对准阈值可设为 5%，避免边界抖动。采用基于帧时间的持续时长，不能用“收到 10 次回调”代替时间，也不能让浏览器停顿的一段时间算作稳定。

缩放、滤镜过渡后重新累计稳定时长。主体移动、追踪降级、目标偏离、最近帧过旧、页面隐藏或用户取消，任何一个发生都取消自动快门。建议最近有效采样不超过 250 毫秒；性能达不到时降级到手动快门。

用户启动前必须能看见本轮将自动拍一张，以及点击会上传一帧。无需每次弹出重复确认。访问口令未解锁时先解锁；不能在用户输入口令后悄悄拍摄，必须回到明确的启动动作。

实现方式使用单调递增的 `runId` 和每轮独立的 AbortController。所有 fetch、Worker 消息、缩放动画和候选帧回调都检查 runId。进入 CAPTURING 前同步设置 `captureCommitted=true`，每轮只能提交一次；即使重复事件或异步回调交错，也不得重复生成照片。

手动按快门时取消本轮自动调度，只拍一张当前取景照片。引导模式暂不叠加原有 3/10 秒倒计时，进入时明确展示 AI 自动拍摄模式，退出后恢复原设置。页面隐藏必须停止摄像头及本轮；返回前台不会自动重启或自动拍照。

## 九 预览 滤镜和照片导出

采用同一份不可变参数驱动预览和导出：

```js
const captureConfig = {
  runId,
  sourceWidth,
  sourceHeight,
  crop: {sx, sy, sw, sh},
  mirrored,
  filter: {id, strength},
  aspectRatio,
  lockedFrameId
};
```

首版可以保留 video 的正常预览，并通过变换正确的容器实现数字裁切，或使用 Canvas/WebGL 统一渲染。无论选哪一种，都要证明预览的主体位置、裁切边界、比例及镜像和保存照片相同。CSS filter 与现有 `applyPixels()` 有潜在实现差异，要用固定色卡比较；若差异明显，使用统一的色彩矩阵或着色器，而不是声称完全一致。

最终候选照片取自实时 video，不能保存最初上传给 AI 的静态参考图。首版将自动数字倍率上限设为 2×，同时按实际原始画面动态降低上限。建议输出短边不低于 720 像素且总像素不低于 100 万；如果原始视频本就低于这些要求，保持 1× 并展示实际分辨率。禁止插值放大后宣传成高像素原生照片。

AI 返回的 `scale=0.5` 只是建议，不保证最终允许 2×；实际倍率由当前几何和画质预算决定。数字裁切无法获得原图之外的场景；已经处于 1× 时不能通过 CSS 缩小制造“超广角”。

自动滤镜从现有五种预设中选，首版对人像采用保守强度，保留“原片”还原。建议先应用 AI 强度并允许用户在预览后修改；不要在后台每帧重新选滤镜。选择“原片”是还原滤镜，不应含糊地改变已确定的构图；若提供整张未裁切原始帧，应单独命名。

自动快门可在稳定后于约 200–400 毫秒内采集 3 个独立帧。对同一最终裁切、同一缩小尺寸、未加滤镜的亮度图计算清晰度；仅在没有明显运动和曝光突变的候选之间比较。清晰度分数不是主观照片美感或准确对焦保证。逐张处理并释放不需要的高分辨率缓存，避免长期保存多个 800 万像素 RGBA 画布。

导出继续使用 JPEG 及现有分辨率上限。网格、目标圈、箭头和文字不得写入照片。照片仅暂存于页面内存，刷新前须保存。系统分享需用户触发，不得在自动拍照完成的异步回调中直接调用 `navigator.share()`。[Web Share 依据](https://www.w3.org/TR/web-share/)

`.openai/hosting.json` 是旧 Sites 站点记录，保留即可。只部署现有 Render，不新建同名付费实例、不改变套餐、不部署到旧 Sites。

## 十二 测试和验收标准

### 纯函数和接口

| 测试 | 预期 |
| --- | --- |
| 同一点经完整坐标链和反向链往返 | 误差在浮点容差内，三种比例和镜像均正确 |
| 右侧目标，手机向右转，背景向左移动 | 目标正确靠近中心，不反向提示 |

| 数字缩放后照片导出 | 裁切与预览一致，主体框保留，边界不越界 |
| 新旧 AI 接口 | 旧契约保持；新字段全部校验；未认证不产生 provider 调用 |

| 并发访问新旧接口 | 共用并发、冷却与额度，不能翻倍调用 |

| 后台、旋转屏幕、镜头切换 | 本轮失效，自动拍摄锁不再提交 |

追踪测试应包括有纹理合成图的已知运动、运动前景覆盖背景、模糊、暗光、白墙、遮挡、突变，以及若有授权素材的真实录屏序列。不能只测试公式或返回写死的“追踪成功”。记录目标误差、丢失时刻和是否误触发快门。

### 浏览器端到端

使用可重现的 Playwright 测试和假相机、模拟 Gemini 返回。截图只是 UI 证据，必须另有断言验证坐标移动、状态转换和最终照片内容。

必要场景：未配置和重新检查、错误/正确口令、分析超时、错误返回、移动参考图、对准后稳定、自动缩放、滤镜应用、只拍一次、手动取消、连续点击、跟踪丢失、照片下载、重新开始、320px/390px 宽度、前后台切换。验证普通拍照发出 0 次 AI 请求；每轮成功引导正常发出 1 次。

默认自动测试不带真实 Key、不产生付费调用。真实 Google 调用使用用户现有的受保护页面测试；不要把生产 Key 拉到本地日志或测试文件。可记录延迟、模型名、结果是否有效和错误类别，不记录照片内容及秘密。

### 真实 iPhone

记录 iPhone 型号、iOS/Safari 版本、视频实际尺寸、照片比例和网络状态。至少验证以下项目：

1. Safari HTTPS 权限正常；打开相机后拍照、导入、保存等旧功能不退化。
2. 静物、静止人像、室外风景各进行 5 次引导。初步目标为每组至少 4 次在 15 秒内完成对准至出片；这是验收目标，必须填写实际成绩。
3. 稳定画面下追踪更新中位数达到 10 次/秒，目标反馈不过度跳动；低性能时明确降级，不误拍。
4. 每次取消、遮挡、突然转身、锁屏和切后台均不自动拍摄。误拍应为 0，失败案例必须修复或关闭自动模式。
5. 连续使用 10 分钟，没有明显内存持续增长、相机冻结或控制失效；记录无法测量的指标，不编造。
6. 预览和成片的裁切、比例、镜像一致，网格不入照片；真实照片 App 中能找到保存结果。
7. 至少用一组日光、一组室内照片检验 Gemini 规划，不把结构化 JSON 成功等同于构图好看。
