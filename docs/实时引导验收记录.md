## 0.4.2 裁切失败循环修复

用户真机反馈：目标已对准却不断提示角度无法容纳构图，按提示调整后追踪丢失，被迫重新分析。代码复现：AI返回scale=1，仅绕画面中心旋转0.005弧度（约0.286°），旧lockCrop因旋转外接矩形超出整幅而报错；catch又回到GUIDING，每400毫秒重复尝试。原测试以scale=.7为主，未覆盖全幅建议与微小旋转组合。

修复：优先保留AI期望范围，受当前视频边界约束时在不裁掉主体、不改变比例/画质底线的前提下适配裁切大小与位置，界面标示已适配。若不存在可行解，进入MANUAL终止状态，释放追踪，白色快门仍可使用；旧帧与后续回调不能重启或误拍。未放宽真实追踪丢失保护，也不增加Gemini调用。

验证：42项Node测试和20个模块语法检查通过；27项Chromium浏览器测试全部通过（约1.7分钟），日志为 `qa-results/browser-0.4.2.log`。新增三比例/高低分辨率/近全幅/旋转与剪切组合，以及不可行主体停止状态。浏览器使用合成图像像素和真实OpenCV Worker、模拟provider；不是iPhone复测。0.4.2真机自动拍摄与相册保存仍待用户确认。

## 0.4.1 灵敏度调整（2026-10-06）

用户对0.4.0真机反馈：目标圈会追踪，但小幅转动手机常被当作主体移动；已对准后的手抖频繁打断快门。0.4.0已发布至既有Render并按授权开启实时功能，本次授权继续提交部署。

本版以背景仿射拟合补偿轻微角度变化，放宽累计像素残差；主体不确定等待最多600毫秒恢复，等待期间不拍摄，也不重新调用Gemini。圆圈显示和判定半径统一为取景器短边7.5%，在实际缩放预览坐标下检查；对准/缩放/再次稳定为400/450/300毫秒，容忍轻微手抖。保持参考有效期、新鲜度、主体完整性、快速扫动限制和取消隔离。

本轮语法检查20个应用模块、39项Node测试、24项Chromium浏览器测试全部通过，320/390宽度截图检查通过。浏览器全套耗时约1.4分钟，日志为 `qa-results/browser-0.4.1.log`。新增用真实Worker处理合成角度/剪切图像的测试，区分背景共同移动与独立主体移动；新增持续手抖仍只拍一张/一次AI请求、圈外不拍及短暂主体误差恢复的回归测试。合成像素和模拟provider不是真实iPhone/Gemini；旧版10分钟结果不能当成本版重新完成的长测。

本版iPhone复测：室内静物、小幅左右转手机、圈内轻抖、圈外移动、拍摄中取消和保存到照片App，结果待用户记录。没有声称所有三维视差均可补偿。

## 自动测试范围与证据

复现：`npm ci`、`npm run check`、`npm test`、`npx playwright install chromium`、`npm run test:browser`。

浏览器：Windows / Chromium 141.0.7390.37，Playwright 1.56.1。合成摄像头为1440×1920、30fps canvas视频流；tracker最长边480。provider由测试服务器模拟，真实模型调用数为0。整个图像追踪引擎、接口、界面和导出代码实际执行，不模拟“追踪成功”。

- 三种比例、镜像正反坐标链、目标越界、变换顺序、异常几何、分辨率限制。
- 新旧接口共用并发、冷却和日限额；未授权/错误比例/非法输入不进入provider；静态资源白名单和私有文件隔离。
- 合成平移/旋转/缩放误差；移动主体、白墙、强模糊、极暗无纹理、遮挡和突然换景的停止路径。
- 错误/正确口令、配置诊断与刷新、旧单帧裁切、正常相机0次AI请求；每轮成功引导1次请求。
- AI分析期间的移动、20秒超期、取消后迟到AI/Worker结果、停帧、重复点击、捕获边界取消、重新开始。
- 比例、镜头、方向、后台变更取消；后台结束所有视频轨道。这里后台/方向是测试事件，不能替代Safari系统行为。
- 数字缩放、滤镜、原片还原不改构图、JPEG下载、320/390px布局和取景器内取消。
- 固定色卡验证新统一renderer在三比例、镜像和五种滤镜下的预览/导出像素一致。旧普通相机仍采用原CSS预览，未把这个测试扩大宣称成所有真实照片颜色完全一致。
- 生成成片中心红色标记与尺寸、灰阶通道均有断言；不是只凭截图判通过。

截图为测试素材：`qa-results/guide-tracking-390.png`、`guide-tracking-320.png`、`guide-review-390.png`、`legacy-320.png`。它们不是实拍照片或最终产品演示。

10分钟结果：`npm run test:soak` 实际运行600.06秒，33轮Worker创建/销毁、6133帧（含33帧初始化，6100帧有效追踪）；平均处理约10.22帧/秒，Worker处理耗时中位14.5ms、P95 15.6ms。WASM线性内存分配容量每轮均为134,217,728字节（128MiB），无计算失败。测试使用静态有纹理合成图，并模拟每18秒结束参考轮次；不是10分钟连续同一参考的可靠性证明。仅测得WASM容量，没有测到进程总驻留内存/全部JS堆，因此不据此宣称无内存泄漏或Safari性能达标。详细JSON在`qa-results/tracking-soak.json`。

## Gemini 手册接入与尚缺验收

读取了[照片分析Agent操作手册](LucyCam-照片分析Agent操作手册.md)。判断：完整主体、环境关系、先构图后滤镜、不机械三分或放大适合本项目；滤镜强度和审美效果仍是待实拍校准的初值，不能用模型自评代替人选。

`photo-prompts.mjs`由手册A/B标记生成；每轮固定A+B1或A+B2，不带研究附录，不增加付费调用频率。运行块SHA-256：`b32c6fda8295c32991057ce595fc9fa23a4932d1c29ead1174d3a4a142b519cd`；规则版本`photo-manual-1.0`。API模拟测试检查实际发给provider的systemInstruction正文等于生成的规则，并非仅检查文件存在。

新接口额外强制无法引导时完整原图/original0；portrait超40拒绝，不静默把mono100改成mono40后声称黑白。接入规则不代表Gemini已认可手册；目前没有实际Gemini独立评审答复或实拍美感比较。发布后通过现有受保护页面送出经用户授权的当前帧，记录几何通过、误裁、画质与用户原图/建议盲选。无需在聊天提供Key或口令。
