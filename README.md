# LucyCam

中文手机网页相机。普通拍照与滤镜在浏览器本地完成；点击「AI 构图」时，仅将当前画面缩小后经 Render 中转给 Google Gemini，返回构图建议和裁切预览。0.5.0 提供已在现有 Render 开启的实时引导试用：本地追踪、目标对准、数字裁切、滤镜及单次自动拍照，已收到真机灵敏度及裁切失败循环反馈，本版调整仍待 iPhone 复测。

演示网址：https://lucycam.onrender.com

代码仓库：https://github.com/markcao0315-eng/LucyCam

## GitHub 与 Render 部署

仓库根目录就是本地 `lucycam-web` 目录。GitHub 顶层应直接看到 `package.json`、`server.mjs` 和 `render.yaml`。

1. 在 Render 创建 `LucyCam` Project，环境使用 `Production`。
2. 添加 **Web Service**，连接 GitHub，选择 `markcao0315-eng/LucyCam` 私有仓库。只授权此仓库即可。
3. 按下面的配置部署：

| 字段 | 值 |
| --- | --- |
| Name | `lucycam`（已被占用时加后缀） |
| Language / Runtime | `Node` |
| Branch | `main` |
| Root Directory | 留空 |
| Build Command | `npm ci && npm run check && npm test` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| Environment variable | `NODE_ENV=production` |
| Instance | 初次连通测试选 Free；实际使用可换常驻付费实例 |

也可以用仓库的 `render.yaml` 创建 Blueprint。它默认创建一个 Free Web Service；手动 Web Service 与 Blueprint 二选一，避免重复创建。当前不需要数据库或持久磁盘。未配置 AI 时，普通拍照仍可使用。

Render 自动设置 `PORT`；程序监听 `0.0.0.0`，运行版本由 `.node-version` 指定为 Node 24。

部署成功后打开 Render 实际返回的 HTTPS 网址。`/healthz` 应返回 `{"status":"ok"}`，部署本次代码后 `/api/status` 显示版本 `0.5.0`。`aiComposition: true` 仅表示配置齐全，不代表已经验证 Google Key 的有效性。

GitHub 私有仓库只控制源码访问；Render 的 Web Service 网址默认可公开访问。相机页面可公开使用，收费 AI 接口要求家庭访问口令。

API 密钥放在 Render 的 Environment 中，不写入前端代码、聊天或 GitHub。`.env` 和日志已在 Git 忽略规则中；`.env.example` 仅作配置说明。

## 配置 AI

在现有 Render Web Service → Environment 中添加并保存部署：

| 变量 | 值 |
| --- | --- |
| `GEMINI_API_KEY` | 你自己的 Google Gemini API Key |
| `LUCYCAM_ACCESS_CODE` | 自己设置的至少 12 位私人口令，手机上输入这个口令 |
| `GEMINI_MODEL` | 可选，默认 `gemini-3.1-flash-lite` |
| `AI_DAILY_LIMIT` | 可选，默认每 UTC 日 200 次尝试 |
| `AI_HOURLY_LIMIT` | 可选，默认每 UTC 小时 60 次尝试 |
| `LIVE_GUIDANCE_ENABLED` | 实验功能，只有字符串 `true` 开启；默认关闭 |

手机刷新页面，开启相机，点击「AI 构图」，输入家庭口令解锁，再点击一次开始分析。绿色框表示 AI 建议保留的范围；点「预览这张裁切照片」，再保存到相册。裁切使用手机内存中的较高分辨率原帧，上传的只是最长边 1024 像素的 JPEG。滤镜在导出时本地应用，AI 读取的是无滤镜画面。

如果按钮显示 AI 未配置，检查两个必填变量和口令长度，再确认最新部署成功。若出现 Google 服务错误，检查 Key、Gemini API 权限、所选模型和项目额度。配置变量后仍需在手机实际点击一次验证；自动测试不使用真实 Key，也不产生 AI 费用。

口令验证后使用 12 小时 HttpOnly / SameSite=Strict 会话，生产环境增加 Secure；修改口令会使旧会话失效。POST 请求限制为同源 JSON；默认只允许单个分析并发、每 5 秒一次，登录每 15 分钟最多 30 次尝试。调用上限为**单进程内存计数**，重启会重置，多实例各自计数，不是账单硬上限；失败的模型请求也计入次数，无自动付费重试。当前面向单实例家庭使用。

LucyCam 不把照片存入文件、数据库或应用日志，但 Google 会按其服务条款处理上传图片；个人照片建议确认 Google 项目的计费和数据使用设置。[Gemini API 定价与数据使用说明](https://ai.google.dev/gemini-api/docs/pricing)。

官方文档：[Render Web Services](https://render.com/docs/web-services)、[Render Projects](https://render.com/docs/projects)。

## 功能

- 摄像头权限、前后镜头切换，自拍预览与保存均为镜像。
- 3:4 / 1:1 / 9:16 中心裁切；网格和构图参考不写入照片。
- 原片、清透、暖阳、胶片、黑白；可调滤镜浓度。
- 3 / 10 秒定时拍照，前后台切换时停止相机。
- 本地照片导入（保留原比例）、JPEG 导出、系统文件分享和下载。
- 主屏幕图标与安装清单。当前需要联网加载，不保证离线启动。
- 单帧 AI 主体描述、中文构图建议、保持原比例的裁切预览与照片导出；访问口令、调用限额、错误提示。

## iPhone 演示

1. 用 Safari 打开部署后的 HTTPS 网址。旧 Sites 演示版是私有的；新 Render 部署不要求 ChatGPT 登录。
2. 点击「开启相机」，允许摄像头权限。
3. 选择色彩和场景，调整取景，按白色快门。
4. 点「保存 / 分享」，选择「存储图像」。若没有这一项，长按预览图保存。
5. 打开 iPhone「照片」确认保存成功；分享完成不等于已保存。
6. 可从 Safari 分享菜单选择「添加到主屏幕」。不需要 Apple Developer、Xcode 或 TestFlight。

照片只暂存于页面内存，刷新或关闭前应保存。「下载图片」可能进入「文件」而非「照片」。权限被拒绝时，调整 Safari 的网站相机权限后重试。微信等应用内浏览器不作为当前测试目标。

## 开发

Node.js 运行 `npm run dev`，本机打开 http://127.0.0.1:4173 。iPhone 不能把这台电脑的 localhost 当成演示地址，也不要使用不支持相机权限的普通局域网 HTTP 地址。手机请使用正式 HTTPS 网站。

`npm run check` 检查语法；`npm test` 验证裁切、分辨率上限、像素滤镜、后台健康检查、静态资源、私有文件隔离、AI 会话/限额/超时/返回值校验。AI 单测注入模拟 provider，无外部 AI 请求。`npm start` 启动与 Render 相同的服务器，本地默认端口为 10000。本地调试时通过 shell 环境变量传入配置，程序不会自动读取 `.env`。

## 已验证与限制

- Chromium 模拟手机视口与摄像头验证：拍照、3:4/方形输出、滤镜切换、JPEG 下载、本地导入、倒计时、320px/390px 宽度、拒绝权限后的备用路径。
- WebMCP 的可选设置工具已在模拟 registry 下验证；未验证真实支持该接口的浏览器宿主。
- 尚未在真实 iPhone Safari 上验证。镜头切换、分享中的存储图像、HEIC 导入及实际画质需真机确认。
- AI 浏览器流程已用 Chromium 模拟相机与模拟 Gemini 返回验证：错误/正确口令、单次上传、建议展示、裁切尺寸、JPEG 下载、会话保持、320px 排版。真实模型建议质量与真实 iPhone 体验仍需配置 Key 后验证。
- 当前拍照来自相机视频流，尺寸以界面显示为准；不能代表 iPhone 原生相机最高静态画质。导入照片导出上限为 800 万像素且最长边 4096。
- 旧单帧入口的绿色裁切框仍是静态参考。实时入口使用独立本地追踪流程，已接入数字裁切、滤镜与单次自动快门；真实设备体验尚待验收。美颜和精修未实现。数字裁切不能替代原生镜头的光学变焦。
- 未接入商业账号、付款、用户图库、云存储或分析追踪。

`dist/` 是相机前端。`server.mjs` 提供 Render 服务，`ai.mjs` 处理会话和 Gemini 中转，服务端没有第三方运行时依赖。实时追踪使用自托管 OpenCV 4.13.0，来源、哈希和许可证见 [第三方运行文件](docs/第三方运行文件.md)。`.openai/hosting.json` 保留旧 Sites 演示站标识，Render 不使用这个文件，GitHub 推送不更新旧演示站。

## 实时 AI 引导（0.5.0，实时动作指引版）

在现有服务设置 `LIVE_GUIDANCE_ENABLED=true` 才显示「AI 帮我拍」，新收费接口也受开关控制。代码默认关闭；现有生产服务已按用户授权开启并保持开启。无需新服务、GPU、数据库或套餐变更。

1. 后置相机、竖屏，选择比例和场景。前摄仍只支持普通自拍和旧单帧构图。
2. 按钮旁明确显示上传一帧及自动拍一张；首次需家庭口令解锁，解锁后必须再次点击开始。
3. 小幅转动手机，使随图像特征移动的目标圈靠近固定中心准星；中心准星进入圆圈并短暂停留后进入数字缩放、滤镜与自动快门，允许轻微手抖。取景器显示实际数字倍率及裁切尺寸，可随时取消。
4. 每轮只上传一次；Worker 在本机跟踪完整未镜像视频。连续新鲜且可靠的帧才累计稳定时间。主体持续无法确认、模糊、遮挡、停帧或参考超过20秒都会停止，重新分析须再次点击。
5. 比例、镜头、方向、视频尺寸或前后台变化作废本轮。手动快门取消自动流程并拍一张当前取景，AI 模式不叠加原倒计时。
6. 成片取自当前视频的3个独立候选帧，不保存上传参考图。可在预览改色或选「原片（保持构图）」，保存由用户点击分享/下载或长按完成。

从0.4.1起用背景仿射变换补偿小幅转动手机产生的旋转、缩放和剪切，不再把这些变化直接算作主体独立移动。背景内点≥20、覆盖≥6/16网格、主体初始特征≥4；背景累计残差<6跟踪像素、主体累计偏差<8像素/相邻帧偏差<3像素。暂时无法确认主体时最多等待600毫秒，期间不拍摄、不重新上传；恢复后沿用同一参考，持续异常才结束。短暂图像匹配失败先进行有时限的原参考恢复。

显示圆圈和对准判定共用取景器短边7.5%的半径，缩放期间也按实际预览裁切换算。对准400毫秒、缩放450毫秒、再次稳定300毫秒，允许圈内轻微手抖；仅快速扫动（超过短边35%/秒）仍阻止快门。锁定裁切不随手抖漂移，主体超出裁切也会暂停。采样新鲜度≤250毫秒、每轮一次快门及取消隔离保留。这些是根据用户0.4.0反馈调整的试用阈值，尚非真机成功率证明。原视频不足720短边/100万像素时不再放大；其余受画质预算与最多2×数字裁切限制。大幅走动、强视差和移动主体不作保证。

0.5.0 把裁切失败后的手动退出改为实时纠正：黄色框表示图像追踪到的主体，绿色虚线框表示AI构图对应的主体参考位置；箭头与文字提示镜头向左/右转、抬高/压低，主体过大时提示确认身后空间后稍后退。方向和大小由图像计算，不凭动画或加速度假定用户已移动。主体缩小或位置偏差减小时显示“方向对了”，满足条件后继续原轮次自动拍摄，不重新上传。近全幅旋转裁切适配仍保留。

短暂模糊/遮挡时进入RECOVERING，最多2.5秒尝试从最后可靠图像找回同一参考；期间隐藏不可靠目标、不累计稳定时间、不拍摄。若参考无法恢复、主体定位持续不确定或超过20秒，取景器仍保留具体调整步骤，并提示停稳后点击“按当前画面继续”重新分析；不会要求用户自行决定手动构图，不会自动增加收费请求。严重视差、已完全离开画面的主体或长期无纹理画面仍不能凭空定位。

“开启动作辅助（可选）”通过用户点击请求DeviceMotionEvent权限，只监听本页动作。竖屏下转动速度可辅助提示抬高/压低或慢一点；线性加速度仅表示正在移动，不积分成前后距离、不认定已经后退。是否拉开合适距离以实际图像中主体大小确认。无API、拒绝权限、空值或过期数据时继续图像引导；取消、拍完、后台和方向变化移除监听。权限与轴向能力依据 [W3C Device Orientation and Motion](https://www.w3.org/TR/orientation-event/)；Safari真机弹窗、轴向和体验尚待复测。


## Gemini 摄影规则

[照片分析 Agent 操作手册](docs/LucyCam-照片分析Agent操作手册.md) 是构图规则来源。服务端固定发送 A 核心规则 + 当前接口对应的 B1/B2，不发送 C–E 研究附录，不接受浏览器自定义模型或系统提示词。旧 `/api/compose` 的响应合同保留；新 `/api/guide-plan` 复用同一会话、并发和限额。

规则强调完整主体、环境关系、明确改善才裁切、自然且保守的滤镜；无法引导时使用完整原图及原片滤镜停止。portrait强度超过40的返回会安全拒绝，避免把mono40误称为黑白。规则版本 `photo-manual-1.0`，部署后可在 `/api/status` 的 `aiRulesVersion` 核验。修改手册A/B后执行 `npm run prompts:build` 更新服务端生成文件；测试核对正文与哈希防止规则漂移。

这表示代码已接入手册，不代表真实 Gemini 已认可手册或照片更好看。没有进行生产调用或审美盲测；需获授权的实拍照片，通过现有受保护页面验收。密钥和口令继续只留在 Render，不放聊天、测试或仓库。

## 可重现验证与回滚

`npm ci` → `npm run check` → `npm test`；首次浏览器验证先运行 `npx playwright install chromium`，随后 `npm run test:browser`。浏览器测试启动临时本地服务器，使用合成图像摄像头与模拟provider，但图像追踪运行真实OpenCV；不触发真实Gemini费用。额外10分钟追踪生命周期检查：`npm run test:soak`，结果写入忽略目录 `qa-results/tracking-soak.json`。短时诊断可通过 `SOAK_SECONDS` 调整，不能把缩短测试报告成10分钟。

[当前验收记录](docs/实时引导验收记录.md) 区分自动测试、真实Gemini和真实iPhone。旧相机已跑回归；完整iPhone拍摄成功率、10分钟整机内存、相册保存及真实流程录屏仍待用户设备验证。

用户已授权本次0.5.0提交和发布，只使用现有GitHub/Render；部署后核验 `/healthz`、0.5.0状态、规则版本和Worker/vendor资源。现有服务保持实时功能开启，本版真实设备复测另行记录。优先关闭 `LIVE_GUIDANCE_ENABLED` 并重新部署回滚新入口和新接口，旧相机/单帧AI保留；必要时正常revert或回滚Render已知可用部署。不修改费用方案或旧Sites。
